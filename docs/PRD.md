## 2. 产品概述

MemoEcho 是一款面向 macOS 的语音 + AI 输入助手。用户通过全局快捷键触发录音（单按／双按切换，或按住说话），录音结束后自动完成语音识别、文本润色，并将结果写回当前焦点应用。

首版产品不是系统级输入法，而是菜单栏常驻应用。产品重点是用最短路径实现“语音输入 + AI 整理”的稳定闭环，降低系统输入法开发复杂度，同时保留未来升级为真正输入法的架构空间。

## 3. 目标与非目标

### 3.1 产品目标

- 在 macOS 上提供可常驻运行的全局语音输入能力。
- 首版优先优化中文短语音输入体验。
- 使用本地离线 ASR（基于 `SenseVoiceSmall-onnx`）或云端 ASR 完成语音转写。本地模型外置存储于用户目录 `~/.memoecho/models/sensevoice-small-onnx/`，通过首次使用引导或设置页下载。
- 用户可在设置中手动选择 ASR 平台（本地 `SenseVoice`、腾讯云、阿里云、阿里云百炼、火山引擎、科大讯飞、OpenAI 兼容）。
- 通过本地降噪、个人词典与 AI 润色提升中文短语音识别落地质量。
- 接入用户自定义的 OpenAI 兼容大模型服务完成文本纠错与保守型结构化处理。
- 在调用配置好的 OpenAI 兼容服务时，默认按单次会话附带当前聚焦窗口上下文帮助消歧：应用/窗口信息、可见文字、选区、光标附近文字和清理后的网页地址。通用设置提供默认开启的“参考窗口上下文”开关，关闭后不发送窗口上下文；敏感场景仅保留应用和输入控件类型等基础信息。
- 在常见桌面应用中稳定完成文本注入。

### 3.2 非目标

- 不实现 macOS 系统级 Input Method。
- 不支持多种 LLM 协议，仅支持 OpenAI 兼容接口。
- 不支持自定义提示词、风格模式、temperature、max tokens 等高级参数。
- 不支持保存音频历史。
- 不做 agent 命令执行、翻译工作流或复杂生产力动作。
- 不做 ASR 平台自动回退；当前选中平台不可用时录音前直接阻止。

## 4. 目标用户

- 有中文语音输入需求的 macOS 用户。
- 希望将口语内容快速整理成可直接发送或写入的文本的用户。
- 有自有大模型服务，或愿意使用 OpenAI 兼容网关服务的用户。

## 5. 核心使用场景

- 在聊天工具中通过语音快速输入较自然、可直接发送的中文句子。
- 在笔记类应用中用语音输入段落，并自动完成基础纠错和标点整理。
- 在浏览器表单、搜索框、输入框中通过语音替代部分键盘输入。

## 6. 核心用户流程

### 6.1 首次使用流程

1. 首次启动自动打开独立引导窗口的欢迎页，副标题为“多说话，少打字。”；以精简的聊天卡片配合真实 HUD 样式演示回复朋友：只保留上方头像与消息气泡，以及下方独立圆角输入框及底部工具栏，不展示用户名、左侧会话列表、搜索框、窗口控制点或单独的聊天标题栏。聊天卡片上沿以直角贴齐演示背景顶部，不保留顶部圆角；底部圆角、底部位置和输入框大小不变。对方提出问题，用户用语音回答。聊天卡片有独立的不透明底色，不将聊天内容直接铺在背景图上。循环展示“唤起语音 → Thinking → 完成填入文字”，填入后停留片刻，不自动发送消息。仅使用虚构示例，不复制参考截图中的真实联系人或内容，不展示应用 Logo，欢迎页不计入步骤，用户点击“开始设置”。
2. `1 / 5` 语音识别：选择本地 `SenseVoice` 或现有云端 ASR 平台。卡片保留本地／云端主图标，不叠加语音转文字的装饰图标。本地模型必须下载成功后才能离开本步；下载期间居中显示约占页面宽度三成、不回退的整体进度条，并禁用继续操作，所有文件校验完成后才显示 100%。云端配置必须经真实请求验证成功。
3. `2 / 5` AI 模型：围绕语音记录灵感的产品设计，对比全中文的原始转写与润色结果；结果与欢迎页语音回复共用同一文案。示例突出明确改口后的最终想法，而非中英混合翻译：结果仅用强调色文字和淡色底纹标出“先把语音入口做起来”；原文用删除线、系统红色文字及淡红底纹标出“嗯…”、“先把分类做起来，啊不对，”、“吧”、“，嗯，那个，”、“然后”和“呃，就是”。删除标记仅覆盖改口前的内容及口头赘词，删去后剩余文本与结果完全一致。VoiceOver 同时说明删除片段和保留的最终想法，不仅靠颜色传达。此为静态产品演示，不标注为模型实测输出，也不保证实际模型逐字生成相同内容；不在打开页面时请求模型，本次文案修改不改变运行时 Prompt。配置 `Base URL`、`API Key`、`Model` 并完成验证，模型列表获取失败时仍可手动填写 Model。
4. `3 / 5` 系统权限：完成麦克风和辅助功能授权，分别展示状态与操作。权限名称、状态和操作按钮文案与设置页共用：麦克风展示“尚未请求／已授权／已拒绝／受限（由系统策略控制）”，辅助功能展示“未检查／已授权／未授权”，未检查时操作为“检查权限”；其余按钮为“请求权限”（系统请求期间为“请求中…”）或“打开系统设置”。麦克风临时授权弹窗结束后，若从 MemoEcho 活动窗口发起而系统短暂将其他应用带到前台，则恢复原 MemoEcho 窗口；对回调后短时间内才出现的浏览器或系统设置抢焦点再检查一次。从其他应用发起或短暂恢复窗口期之后用户自行切换应用时不抢焦点。每次应用启动都不主动查询辅助功能信任状态，包括曾拖入或完成设置的用户，避免用户从系统列表删除应用后又在启动时被重新加入；未查询时显示中性的“未检查”，不显示未授权警告。用户打开权限页（含引导中的权限页）、点击授权入口或主动按快捷键准备录音时即时检查真实权限；权限页重新激活及授权流程从系统设置返回时复查。已授权时不展示重复授权引导。用户实际拖入应用后才开始持续复查，其他主动检查不启用后台轮询。辅助功能入口打开系统设置后，在设置窗口上层靠下位置显示可移动的简洁浮窗，浮窗只保留可拖动应用图标、“拖入并启用辅助功能”和关闭按钮，不显示箭头或切换指引。浮窗只定位一次，不随系统设置窗口移动，也不随其显示／隐藏而变化；拖入系统设置后关闭浮窗并开始权限复查，检测到授权成功时也自动关闭，允许用户自行关闭。只有系统权限检测结果决定授权状态，拖拽本身不视为授权，也不自动推进引导；辅助功能授权结束后不主动切换前台应用。两项均已授权后显示“继续”；受限时禁用继续并展示设置页相同的限制说明。卡片保留简短用途说明，页面下方不额外显示用途说明、授权等待文案或加载动画，保留按钮防重复操作。
5. `4 / 5` 全局快捷键：新配置默认使用右 Command 单键，用户需明确接受或重新录制；已有配置中的快捷键不自动覆盖。新快捷键注册成功后才保存，失败时保留原配置。只有语音、AI、权限和快捷键注册全部就绪，“完成设置”才将快捷键确认与首次设置完成状态一次写入配置，然后进入可选的第 5 步；此时菜单栏“设置”已可用。
6. `5 / 5` 设置完成：所有必要项就绪时明确展示完成状态，试用是可选操作；进入本页时自动聚焦紧凑的可编辑测试框，空框提示“按下快捷键 {当前快捷键}，开始说话…”，快捷键展示沿用设置页的可读格式。保留一句示例，不另加键帽或底部重复提示。本页位于前台时，快捷键启动页内试用，结果仅回填本页；切到其他业务应用时，快捷键正常唤起 HUD 并输入到目标应用。若就绪项随后失效，不聚焦测试框，恢复入口转到对应设置页；不展示页内红色错误提示。
7. 用户可重复试用，或直接点击“开始使用”关闭引导；第 5 步不再写入完成状态，也不提供“上一步”。欢迎页和第 1 步均不提供“上一步”；进入第 1 步后不能返回欢迎页，第 2～4 步可返回上一配置页。关闭窗口取消未完成试用；完成配置或授权不会自动录音。

引导视觉与交互：

### 6.1.1 录音前检查与恢复

- 每次准备开始录音前，动态检查快捷键注册、麦克风、辅助功能、本地模型文件或云端 ASR 验证，以及当前 LLM 配置验证状态。
- 首次设置未完成时不创建日常输入 session；按快捷键只打开或聚焦未完成的向导。已有配置文件损坏时打开设置页修复，不重开向导。
- 已完成设置后发生权限撤销、模型文件丢失或配置失效时，打开对应设置页；修复后仍需用户再次触发，不自动录音。
- 第 5 步在前台时快捷键启动页内试用，切到其他业务应用后快捷键启动日常输入；其他设置步骤及授权过程中不创建 session。
- 引导完成状态不能替代当前就绪检查；恢复配置后仍须由用户在目标应用中再次主动触发录音。

### 6.2 日常使用流程

1. 用户在任意应用中聚焦输入区域。
2. 用户按下全局快捷键开始录音。
3. 用户按所选方式结束录音；按住方式松开提交。
4. 录音期间，MemoEcho 在后台根据静音停顿自动切分音频分段，提前对已完成分段进行 ASR。
5. 用户结束录音后，识别最后一段音频，所有分段 ASR 文本按时间顺序拼接。
6. 客户端调用 OpenAI 兼容接口进行文本处理。
7. 仅当 LLM 成功返回可用结果时，客户端才进入文本注入。
8. 客户端将最终文本一次性写入当前焦点应用。
9. 若 LLM 配置不完整或请求失败，则直接提示错误，不注入任何文本。
10. 菜单栏状态恢复空闲。

## 7. 产品形态与交互

### 7.1 应用形态

- 菜单栏常驻应用。
- 无主编辑窗口。
- 设置页或引导页打开期间显示 Dock 图标，支持 ⌘Tab 切换；最小化时保留入口，点击 Dock 恢复最近使用的窗口及原页面。全部设置／引导窗口关闭后恢复仅菜单栏驻留，不退出应用。HUD、处理提示和授权辅助浮窗不触发此行为（Issue #9）。
- 设置页为唯一完整配置界面。
- 关于窗口用于展示当前版本、`自动检查更新` 开关和 `检查更新` 按钮。
- 更新检查与安装在应用内完成，不跳转网页手动下载安装。

### 7.2 快捷键交互

- 首版仅支持单一全局快捷键。
- 快捷键录制支持普通组合键、纯修饰键，以及区分左右侧修饰键的组合。
- 设置页用键帽 token 展示当前组合；录制中提示按下新快捷键或松开保存，Esc / 外部点击 / 窗口失焦取消并保留原快捷键。
- 新快捷键必须注册成功才保存；注册失败时恢复原监听和原配置。
- 支持 MacBook 的 `Fn`／🌐 键（含单键 `Fn`，以及 `Fn` 与其他修饰键的组合）；录制与触发基于 `flagsChanged` 物理按键状态监听实现。
- 若 macOS 系统设置中「按下 🌐 键时」已配置切换输入源、显示表情等动作，用户需在系统设置中改为「无操作」，否则系统动作会与快捷键同时触发；全局 `NSEvent` 监听只能观察事件，不能拦截系统动作。设置页在选中 `Fn` 时提示此限制。
- 录音方式可选「单按 / 双按 / 按住」，默认单按；具体行为见 [Issue #8 录音方式](./plans/hotkey-recording-modes.md)。
- 单按方式下，纯修饰键快捷键按下时先显示待确认 HUD，但不启动录音；若直接松开则确认本次切换并开始或结束录音。
- 单按方式下，纯修饰键按住期间若参与其他组合键（如 `Right Command + M`），释放后取消待确认 HUD，不开始录音，也不结束已有录音。
- 在 `识别中 / 润色中 / 注入中` 阶段再次按快捷键时忽略，不作为取消入口。
- 不支持多快捷键动作体系。

### 7.3 状态反馈

应用图标使用白底、黑灰色倾斜飞碟与淡出光束。菜单栏使用固定的正立飞碟单色图标，保留圆顶月牙和底部小圆罩，由系统适配浅色／深色外观；不为会话各阶段增加独立图标。录音、处理与失败通过 HUD 和菜单内容反馈。

HUD 浮窗已具备以下反馈能力：

- 录音态：`X + 声波 + ✓`，支持 ESC 取消
- 处理态：`THINKING` 黑白灰渐变动画（不拆分为识别/润色/注入阶段）
- 成功后直接消失，不展示单独的完成态
- 失败态：根据错误分类展示短文案（`缺少权限`、`资源缺失`、`没听清`、`识别失败`、`润色失败`、`写入失败`）
- 用户取消后直接消失，不展示单独的取消态
- 短录音（<500ms）静默取消，不显示失败态

HUD 不展示底层错误详情、ASR 原文、LLM 输出或长说明。

HUD 展示规则（Issue #12）：

- 胶囊和透明面板按同一份测量结果调整宽高，保持屏幕底部锚点，变高时向上展开；录音会话内不因鼠标移动跳屏，屏幕移除时重新定位。
- 候选、正常录音、Thinking 保持 105.6 × 31.2pt；“没收到声音”按完整文本扩宽，取消/结束按钮保持可用。
- 无动作失败停留 2.4 秒；已复制 1.2 秒；模式提示 650ms。提示时间从窗口显示完成后计算，过期任务不得提前隐藏新状态。
- 减少动态效果时声波与 Thinking 使用静态状态；新词/Thinking 穿透鼠标，录音/恢复动作保持非激活窗口。
- 完整方案与验收矩阵见 [HUD 展示优化](plans/hud-display-refinement.md)。

系统通知用于提示：

- 配置错误
- 权限缺失
- 本次处理失败
- 注入失败

交互音效：

- 开始录音使用 A「柔和双音」上行提示（约 349→440Hz），结束录音使用配套下行提示（约 440→349Hz）。双音间隔 145ms，采用接近纯音的柔和音色与少量泛音；Start 第二音稍强，End 第二音稍弱，不叠加延迟回波。
- 开始音有效时长约 0.412 秒、结束音约 0.410 秒（按 −60 dBFS、10ms RMS 窗口测量），文件总长均为 0.43 秒，RMS 均为 −32dBFS。应用逐字节采用用户确认的试听资源；可通过现有“交互音效”开关关闭。
- 提示音时序参考 Typeless：录音采集启动后，输入输出为同一设备时延迟 1200ms；否则输出为 AirPods 时延迟 300ms；其他情况立即播放 Start，不轮询稳定性、不自动重播、不发送周期静音保活。正常结束时先播放 End，约 100ms 后关闭采集；短于 500ms 的录音仍立即静默取消。停止或取消会取消尚未播放的 Start。音效开关关闭时不播放提示音，正常结束仍遵循相同的 100ms 采集关闭时序。

### 7.4 注入失败恢复

菜单栏恢复入口（Issue #13）：

- 首层只显示“恢复上次输入”子菜单，不展示正文预览或错误全文
- 子菜单根据检查点提供重试、复制最终结果、查看原因和丢弃；复制成功反馈“已复制”，失败保留结果并提示
- 仅当前运行期有效，失败后最长保留 10 分钟

HUD 恢复入口：

- 注入失败时 HUD 显示 `写入失败` + 复制动作入口
- 点击后给出 `已复制` 反馈
- 复制动作必须由用户主动触发，不得自动写入剪贴板
- 仅用于文本注入失败；权限失败、ASR 失败、LLM 失败不提供 HUD 复制入口
- 带动作的失败 HUD 将短分类与独立按钮分区，只有点击按钮才执行动作；按钮文案使用“重试 / 设置 / 复制 / 继续”，完整显示；左侧短原因说明失败阶段，菜单保留完整操作名称。保留约 5 秒，悬停或辅助功能聚焦时暂停剩余倒计时，离开后继续；消失后菜单栏仍可恢复。ASR、整理、翻译失败提供对应重试，配置或权限错误引导检查设置。防止连续点击重复执行，不抢原输入框焦点。

### 7.5 处理中断

- 当应用处于识别中或润色中时，用户可从菜单栏取消当前任务。
- 取消后不再注入文本。

## 8. 功能需求

### 8.1 菜单栏

菜单栏需包含以下能力：

- 固定提供设置…（首次引导完成后）、关于 MemoEcho
- 至多一个上下文区域：可取消任务优先；活跃任务隐藏旧恢复；空闲时有效检查点显示“恢复上次输入”；无恢复结果但有已确认阻塞时显示“检查设置…”
- 瞬时错误、录音警告由 HUD 展示，不长期堆在菜单
- 麦克风选择子菜单
- 退出应用
- 不提供 `检查更新` 入口

麦克风选择子菜单：

- 一级菜单仅显示 `麦克风`，不额外展示当前设备名称
- 子菜单内包含 `自动选择（推荐）`、`系统默认($当前选择输入设备名)` 和当前所有可用麦克风；新配置默认自动选择，已有选择保持不变
- 当前选择在子菜单中以勾选表示
- 切换后立即保存配置，但仅影响下一次录音
- 录音、识别、润色、注入期间禁用麦克风切换
- 已选设备不可用时，直接切换到系统默认输入，不额外展示不可用提示项

### 8.2 设置页

设置页需包含以下模块：

#### A. LLM 配置

- Base URL 输入框
- API Key 输入框
- Model 输入框；当服务支持 OpenAI 兼容 `/models` endpoint 时，设置页自动获取模型列表供用户选择
- 若服务不支持 `/models` 或获取失败，用户仍可手动输入 Model；手动输入与列表选择可同时使用
- 模型列表仅做 App 运行期内存缓存；相同 Base URL 与 API Key 在缓存有效期内切换设置页或重新打开设置窗口时直接复用，不重复显示加载状态或发起请求
- 缓存过期后保留已有模型列表并静默刷新；静默刷新失败不清空列表或阻断手动输入。Base URL 或 API Key 变化时按新的连接身份加载
- 通用设置提供“参考窗口上下文”开关（默认开启并持久化），说明内容用于辅助 AI 整理和翻译；采集与发送边界见 12.2。

#### B. 快捷键配置

- 全局快捷键设置入口
- 允许将 `Right Command`、`Left Command + Option`、`Control + Option`、`Fn` 等纯修饰键组合作为全局快捷键
- 设置页需明确支持左右侧修饰键的区分录制
- 快捷键以独立键帽展示，左右侧使用“左 / 右”而不是 `L` / `R`；录制入口为“更改…”
- 快捷键仅在监听器注册成功后写入配置；失败时保留原快捷键并在当前行显示错误

#### C. 权限状态

- 麦克风权限状态
- 麦克风权限引导
- 辅助功能权限状态
- 辅助功能权限引导
- 首次使用引导和设置页复用权限状态；麦克风未决定时请求系统授权，已拒绝时打开隐私设置，受限时说明无法直接启用
- 辅助功能未授权时触发系统授权引导；同一时间只处理一个授权界面，重复操作不重复弹窗

#### D. 诊断信息

- 最近一次错误摘要

#### E. 个人词典

- 词条新增、删除、编辑入口
- 用户提交真实词条并通过校验后才写入词典，不创建占位词条
- 词条列表不显示外框，首列标签与上方筛选、下方操作栏和说明左对齐。词条以标签展示，按词条实际宽度从左到右排列，空间不足时自动换行，每个标签右侧常显删除 ×；单击选中，双击编辑，新增和编辑通过 Sheet 完成。标签最大宽度 180pt（含删除按钮），长词单行显示，超出宽度以省略号截断，悬停显示完整词条
- 词典页为居中工作区：列表左上方显示可切换的“全部 / 自动添加 / 手动添加”原生分段选择器，右侧为搜索，操作栏下方提示“双击词条编辑，蓝点表示自动学习。”，不重复解释删除按钮
- 支持按词条文本本地搜索，搜索不影响持久化顺序
- 底部操作栏提供添加、删除，以及收纳在更多菜单中的 CSV 导入、导出入口
- 词条至少包含术语文本
- 设置页仅展示术语文本；`pronunciationHint` 和 `category` 暂不在 UI 中维护
- 自动学习仅针对已验证写入的本次文本：绑定原输入框和插入范围，编辑稳定 1.5 秒且无已知输入法组合/选区时，提取完整中文、英文或混合术语。切换输入框、新会话、取消、清空或大幅改写即停止。
- AI 只判断局部纠正是否为完整专名；返回词必须原样出现在用户修订中并覆盖改动位置。普通改写、孤立拼音和不确定结果不学习。
- 词典页统一使用已有编辑、删除操作，不另设“最近添加”区域或撤销按钮。删除仅移除当前词条，后续满足条件仍可自动学习。只持久化词条，不保存编辑正文。
- 词典标签中的自动学习词在词后显示小蓝点，选中时使用浅色背景并保留蓝点，悬停提示“自动学习”；手动词不显示标记，无障碍朗读保留来源说明。
- 自动学习到新词时，通过 HUD 显示词典图标和完整词条，不加“新词：”前缀、不固定截取 4 字。按实际字体测量，最大宽度 `min(320pt, 屏幕可见宽度 - 32pt)`，最多两行；仅两行仍放不下时在末行尾部省略，不拆 emoji/组合字符。保留原始大小写和词典页完整数据，VoiceOver 读出完整词条。单行停留 2.4 秒，多行 4 秒；空词条不提示，录音/处理中晚到的提示不得抢占当前状态。

#### F. ASR 配置

- ASR 平台选择（本地 `SenseVoice` / 腾讯云 / 阿里云 / 阿里云百炼 / 火山引擎 / 科大讯飞 / OpenAI 兼容）
- 本地模型状态展示与下载入口
- 云端平台最小凭据配置入口
- 云端平台在字段完整后自动执行真实请求验证，状态区展示未就绪 / 验证中 / 已就绪 / 验证失败
- 下载中显示进度与取消
- 已就绪时仅显示完成态，不暴露模型路径、模型版本、重新下载或删除入口

### 8.3 录音能力

- 录音方式可选「单按 / 双按 / 按住」，默认单按；具体行为见 [Issue #8 录音方式](./plans/hotkey-recording-modes.md)。
- App 不设置固定录音时长上限。
- 录音期间根据静音停顿自动切分音频分段，提前对已完成分段进行 ASR。
- 静音持续 1.6 秒且当前段总时长至少 15 秒时触发自动切段。
- 自动切段保留 300ms 段尾静音，避免句尾被切掉。
- 单段达到 55 秒时强制切段，避免超过短音频 ASR 服务边界。
- 用户手动结束时的最后一段不要求达到 15 秒，只要超过短录音阈值即可识别。
- 静音检测应使用动态噪声底 + dBFS 阈值，并保留轻量语音保护，避免长静音或环境噪声触发无意义 ASR。
- 录音时长低于 500ms 时视为误触，静默取消，不进入降噪、ASR、LLM 或文本注入。
- 短录音静默取消不展示错误摘要，不生成注入失败文本，仅允许写入内部诊断日志。
- 若麦克风权限缺失，则不能开始录音，并给出明确提示。
- 若辅助功能权限缺失，则不能开始录音，不进入录音 HUD，并给出明确提示。
- 用户可从菜单栏选择自动选择、系统默认或具体麦克风。自动选择在蓝牙耳机输出、默认输入为蓝牙时优先使用开盖且可用的内置麦克风，否则使用系统默认；系统默认严格跟随系统，具体设备优先尊重用户指定。录音中不自动切换设备。
- 已选麦克风不可用时，不阻止录音，自动切换到系统默认输入设备。

### 8.4 音频预处理与语音识别

- 录音结束后、进入 ASR 前，默认执行本地降噪处理。
- 降噪方案使用开源 RNNoise。
- 默认 ASR 方案为本地 `SenseVoiceSmall-onnx` 离线识别，通过内置 `sherpa-onnx` 运行时加载 ONNX 模型执行。
- 云端 ASR 固定支持腾讯云、阿里云、阿里云百炼、火山引擎、科大讯飞、OpenAI 兼容六个网络服务入口，均以单次短语音、非流式 final text 方式接入。
- 所有 ASR 平台统一走分段编排，包括本地 `SenseVoice` 和云端 ASR。
- 每个分段继续调用现有短音频 ASR Provider，不新增厂商长音频接口。
- 分段 ASR 串行执行，降低 sidecar 并发、WebSocket 并发和云服务限流风险。
- 录音结束后取所有分段 ASR 转写文本按时间顺序拼接，进入 LLM 润色与注入流程。
- 拼接后文本超过 8000 字符时，明确失败，不进入 LLM，不注入文本。
- 任一有效分段 ASR 失败时，整次流程失败，不注入部分文本。
- App 仅内置降噪与 `sherpa-onnx` 运行时；`SenseVoice` 模型必须外置到用户目录，缺失时阻止录音并给出明确提示。
- 当用户选择本地 `SenseVoice` 时，设置页仅展示模型状态和下载/取消等必要操作，不向用户暴露模型路径或模型版本。
- 云端平台不做自动回退，不暴露热词、词表、领域、模型切换等高级参数。
- 云端平台只有在字段完整且已通过一次真实请求验证后才视为可用；字段变更后历史验证结果立即失效。
- 本轮不暴露 ASR 高级参数（模型选择、线程数、热词权重等）。
- 不支持实时流式 ASR partial result；分段缓存和提前 ASR 均在后台完成，用户无感知。

### 8.5 LLM 润色与保守型结构化处理

- 首版唯一 LLM 协议为 OpenAI 兼容接口。
- 用户仅可配置 `Base URL`、`API Key`、`Model`。
- 不暴露 temperature、max tokens、system prompt 等高级设置。
- Prompt 固定由应用内置维护，不向用户开放自定义 Prompt。
- 当输入来自多段分段转写时，Prompt 明确说明输入来自同一次语音输入的连续分段转写，可合并因分段造成的断句，但不得扩写、改写原意或补充事实。
- 个人词典可作为术语参考进入 Prompt，但不得被视为可执行指令。

LLM 文本处理边界如下：

- 允许：
  - 修正 ASR 识别错误
  - 修正常见同音词和错别字
  - 去掉明显口语赘词
  - 轻度书面化表达
  - 自动补自然中文标点
  - 保留个人词典中的专有名词
  - 在结构信号明确时，将内容整理为 `plain_text`、`list` 两类之一
  - 在用户明确自我修正时，以最终明确表达覆盖前述内容（仅限同一次输入内的修正，如"不是 A，是 B""改成…""前面那个不要了"）
- 不允许：
  - 大幅改写原句结构
  - 主动扩写未说出的内容
  - 擅自改变语义、语气、事实
  - 扩展为长邮件、摘要、会议纪要等更强文稿生成

结构化处理范围如下：

- `plain_text`
  - 默认模式，延续现有纠错、标点和轻分段能力
- `list`
  - 当输入明显包含“第一/第二/第三/还有/重点是/分几点”等枚举信号时，可整理为列表
  - 若原话先给出场景句、提醒语或列表引子，再开始枚举条目，应保留这段前言后再输出列表
  - 若列表后还有补充说明、提醒句或备注，应保留在列表后，不得静默省略
  - 仅拆分原有内容，不新增未说出的要点
- 其他口述内容
  - 包括短消息口述、回复口述、转发口述在内，统一按 `plain_text` 保守润色，不进入单独消息格式化模式

### 8.6 输出策略

- 默认输出经保守型结构化处理后的最终文本。
- 仅当 `Base URL`、`API Key`、`Model` 三项均完整时，才视为 LLM 已配置完成。
- 若 LLM 配置不完整，则本次流程直接报错，不注入任何文本。
- 若 LLM 失败、超时、返回无效内容或明显为空，则本次流程直接报错，不注入任何文本。

### 8.7 文本注入

- 用户于 2026-10-10 确认简化注入策略：备份剪贴板 → 临时文本 → 一次定向粘贴 → 约 500ms 后恢复。不再使用 AX 全文确认或 AX 写入回退。
- 绑定录音开始时的目标应用与输入框；保留权限、明确不可编辑/密码框、系统安全输入、目标身份和可检测的组字保护。不根据正文、选区变化或快照不可读阻止正常粘贴。
- 窗口级目标保留原有连续性保护；发送前切换应用或窗口则停止，不主动激活窗口级目标。已绑定字段不得退化为窗口投递。
- 事件发出即收起 HUD，不等待正文回执。发送后不再查询输入框，不重复发送、不补写；结果不表示已取得目标应用的消费回执。
- 剪贴板备份在后台执行，最多等待 1 秒；无法备份、无法写入临时剪贴板或无法发送事件时明确失败，保留手动复制入口。
- 发送后保持约 500ms 的剪贴板消费窗口与注入互斥；期间取消也先完成必要清理，期间用户新复制的内容优先，不覆盖新复制。
- 临时内容标记为临时、自动生成和仅本机使用，主动复制结果仍为普通复制。
- 字典学习独立验证基线；可选 AX 快照只供学习使用，不影响注入完成和 HUD。
- 辅助功能权限在录音开始前校验。窗口身份无法发现同一窗口内切换聊天，窗口级输入仍需保持原聊天位置。

### 8.8 输出结果复制

- 实际发送失败时，在“恢复上次输入”子菜单提供“复制结果”；不自动复制，不展示正文预览。
- 粘贴投递完成后清除本次结果和恢复记录，不保留“未确认写入”状态或复制入口。
- 失败结果仅在内存中最长保留 10 分钟，过期、主动丢弃、退出或下一次投递完成后清除，不落盘。
- 取消、ASR 失败、权限失败、LLM 失败不会生成最终文本复制入口。

### 8.9 从失败阶段继续

- 首版提供用户主动重试，不自动重发请求。恢复与新录音共用单会话互斥；恢复不打开麦克风、不播放开始/结束音效。
- ASR 失败：保留失败分段和未处理分段的音频、已经成功的转写。若错误发生在录音期间，停止采集并封存已录下的尾段，再提示失败；不得先清空分段队列。重试仅识别失败段及后续段，全部成功后才进入 AI。
- 整理失败：保留完整转写，只重试整理。翻译失败：保留润色结果和原目标语言，只重试翻译。成功的上游阶段不重复调用。
- 写入失败：保留最终文本。只有尚未发送粘贴事件且原目标存在时允许重试写入；不自动重试。
- 重试沿用原任务的模式、目标语言、目标输入框和原窗口上下文，不把设置页或当前其他应用作为新上下文；每次 AI 请求前检查当前开关并按内置敏感规则过滤原快照。使用当前 LLM 配置及最新凭据；ASR 保持原平台并读取该平台的最新凭据。
- HUD 按钮使用“重试 / 设置 / 复制 / 继续”；菜单栏将按需动作收纳于“恢复上次输入”子菜单，另提供用户可读原因详情；无最终文本不提供复制。设置修复后由用户手动重试，不自动继续。
- 只保留最近一次可恢复失败，在首次失败后最多保留 10 分钟，重试失败不续期。新录音可以开始；新的可恢复失败会替换旧记录。恢复或新的日常输入成功、主动丢弃、取消恢复、到期或退出时清空；引导试用不创建或清除日常恢复记录。
- 音频、转写和上下文仅保存在内存，不生成录音历史，不写入配置或诊断正文。成功识别的分段音频立即释放；全部识别成功后只保留文字。已经进入恢复请求的数据在取消后等待 Provider 结束释放，迟到响应不得推进阶段或写入。
- 空录音、主动取消的录音、超过 8000 字符的转写不提供无效的重复处理入口。

## 9. 系统状态机

应用处理状态机固定为：

`idle -> recording -> transcribing -> polishing -> injecting -> done`

异常路径补充状态：

- `error`
- `cancelled`

状态规则：

- 同一时间仅允许一个 session。
- 新 session 不得覆盖正在处理中的旧 session。
- 用户取消后当前 session 立即终止。

## 10. 配置项定义

用户配置字段：

- `llm.baseURL`、`llm.model`、`llm.apiKey`
- `general.hotkey`、`general.interactionSoundEnabled`、`general.translationTargetLanguage`、`general.windowContextEnabled`
- `asr.selectedPlatform`、填写过的平台鉴权信息、可选的 `asr.local.mirrorSource`
- `audio.selection`：`automatic` / `systemDefault` / `device`；指定设备时保存 `audio.deviceID`

存储规则：

- 用户设置、连接参数和全部鉴权信息存储于 `~/.memoecho/config.json`（UTF-8 JSON，目录 `0700`、文件 `0600`）；不使用 Keychain。
- 引导进度、与具体配置绑定的验证成功记录及 LLM 接口能力缓存存储于 `~/.memoecho/state.json`，不重复保存密钥原文。删除 config 后启动视为重新设置，同时重置应用状态。
- 下载与验证过程、最近错误仅保存在内存；本地模型就绪情况读取实际文件。未填写的平台不写入配置，已填写但未选中的平台继续保留。
- 快捷键展示文本和设备名称不持久化。登录启动以系统登录项状态为准，操作失败需提示，不写 config。
- 只读写当前格式，不提供历史配置兼容或迁移。
- 个人词典存储于 `~/.memoecho/dictionary.json`，保存用户显式维护和自动学习到的术语，不保存历史输入文本或输入框全文快照。
- 个人词典导入、导出使用 UTF-8 单列 CSV，无表头、每行一个词。导出全部词条且只包含词文本；含逗号/双引号时使用 CSV 引号转义。导入全部归为手动添加：已有自动词转为手动，已有手动词和文件内重复词跳过，去重忽略大小写及 Unicode 规范形式。空行跳过，多列、未闭合引号、跨行词和非法编码整体报错，不部分写入。

## 11. 错误反馈策略

错误对用户只展示简明、可理解的分类文案，不直接展示底层原始报文。

首版需要覆盖的错误类别：

- 麦克风权限未开启
- 辅助功能权限未开启
- 录音数据为空
- 本地识别引擎未就绪
- 本地识别模型缺失
- 本地降噪资源缺失或处理失败
- 本地语音识别失败
- 分段 ASR 失败（任一分段失败导致整次失败）
- 拼接转写文本超长（超过 8000 字符）
- LLM 凭证或模型无效
- LLM 网络异常
- 文本注入失败
- 当前任务已取消

错误展示位置：

- HUD 即时反馈与菜单栏按需恢复入口
- HUD 浮窗（短分类文案）
- 设置页最近一次错误摘要

HUD 短错误分类映射：

| 错误来源 | HUD 短文案 |
|---------|-----------|
| 麦克风/辅助功能权限 | 缺少权限 |
| 资源缺失（引擎/模型/runtime） | 资源缺失 |
| 空音频/空识别结果 | 没听清 |
| ASR 处理失败 | 识别失败 |
| 转写文本超长 | 内容过长 |
| LLM 配置/网络/空响应 | 润色失败 |
| 翻译阶段 LLM 失败 | 翻译失败 |
| 文本注入失败 | 写入失败 |

## 12. 非功能需求

### 12.1 稳定性

- 连续多次触发录音时，不得出现状态串扰或旧结果覆盖新结果。
- 取消后的请求不得继续进入注入流程。

### 12.2 隐私

- 默认不保存音频。
- 不保存历史文本记录。
- 使用本地识别时音频不离开设备；用户选择云端识别时，分段音频发送至所选 ASR 服务。
- 转写文本及开启时采集的窗口上下文发送至用户配置的 LLM 服务。通用设置可关闭窗口上下文；关闭后新会话不采集，后续润色、翻译、手动重试及 thinking 回退请求均不附带上下文（包括应用/窗口元信息）。已经发出的请求无法撤回。不提供应用/域名排除列表。
- 内置敏感保护：密码框、系统认证、密钥输入、密码管理器和终端不发送正文、窗口标题或网址。
- 仅采集录音开始时聚焦的窗口，不截图、不读取其他窗口或标签页；网页地址移除凭据、查询参数和片段，仅保留协议、域名和路径。网页地址不可得时仅省略网址，其他可用字段继续提供。
- 上下文是辅助参考，不是指令；不得将未口述的正文拼入输出。采集失败、超时或焦点改变不阻断录音和识别，保留已取得的基础信息。
- 上下文仅保留于会话/失败恢复的内存中（恢复最长 10 分钟）；Debug 和 Release 均不记录上下文原文。
- Release 构建日志不得输出原始音频、ASR 原文、LLM 输出正文或用户密钥。
- Debug 构建允许输出 ASR/LLM 明文对照日志，用于开发排查，不作为用户数据持久化能力。

### 12.3 可扩展性

- ASR 层保留替换识别引擎的架构空间。
- LLM Provider 层需与 UI 解耦。
- 当前架构应支持未来升级为真正输入法或扩展更多实时反馈能力。

## 13. 技术约束

- 客户端技术栈：`Swift + SwiftUI + AppKit`
- 使用菜单栏应用架构
- 使用 macOS Accessibility API 做文本注入
- 不依赖系统级输入法框架实现首版能力

## 14. 验收标准

### 14.1 基础可用

- 首次启动自动打开独立欢迎页，之后按语音识别、AI 模型、系统权限、全局快捷键、试一下的固定顺序完成五步引导。
- 引导少文案、以操作演示为主；正式步骤使用 `N / 5`，支持深浅色、VoiceOver 和“减少动态效果”。
- 本地模型须下载成功后才能离开语音识别步骤；云端 ASR 与 AI 模型必须验证成功，默认快捷键需明确接受，自定义快捷键需注册成功。
- 任一必要项未就绪，或授权、验证仍在进行时，不创建录音 session；第 4 步完成前不允许日常输入，第 5 步在前台时允许页内试用，其他应用在前台时允许日常输入。
- 完成后撤销权限、删除本地模型或使配置失效，下一次快捷键会打开对应设置页，不重复欢迎页或自动录音。
- 用户可将 `Fn`／🌐 键录制为全局快捷键，在其他应用前台时正常触发。
- 应用可常驻菜单栏并正常响应全局快捷键。

### 14.2 主链路可用

- 用户可通过快捷键触发录音并完成一次语音输入。
- 录音超过 60 秒不会自动停止。
- 录音期间停顿不会结束录音，只会在后台触发分段识别。
- 录音超过 15 秒后，出现约 1.6 秒静音会自动切段并提前 ASR。
- 连续讲话达到 55 秒会强制切段。
- 用户手动结束后，最后一段被识别并参与最终拼接。
- 多段 ASR 文本按时间顺序拼接。
- LLM 能按"同一次语音输入的连续分段转写"处理拼接文本。
- 本地 `SenseVoice` 可返回中文转写。
- 降噪链路可正常处理录音音频。
- LLM 成功时输出经保守型结构化处理后的最终文本。
- LLM 配置不完整或请求失败时不会注入任何文本。
- 文本可在常见应用中成功注入。

### 14.3 失败场景可控

- 缺少麦克风权限时无法录音且提示明确。
- 缺少辅助功能权限时无法录音且提示明确。
- 任一分段 ASR 失败时，整次失败，不注入部分文本。
- 拼接文本超过 8000 字符时，明确失败，不进入 LLM。
- LLM 配置错误时，用户能看到可理解的错误摘要。
- 本地识别失败时，用户能看到可理解的错误信息。
- 注入失败后，用户仍可从菜单栏复制失败文本。
- 短录音 <500ms 仍静默取消。

### 14.4 数据行为正确

- 注入失败文本仅在当前运行期有效。
- 成功注入后失败文本自动清空。
- 应用重启后保留配置，不保留音频和历史文本。

## 16. 结论

首版 MemoEcho 的产品定义为：一款运行于 macOS 菜单栏的中文语音 + AI 输入助手，基于本地降噪、`SenseVoiceSmall-onnx` 本地语音识别、个人词典与用户自定义 OpenAI 兼容 LLM 服务，支持录音期间基于静音检测自动切段与分段串行 ASR，提供“快捷键触发录音，自动处理，直接注入文本”的稳定输入体验。


### 录音设备异常与电平显示（2026-09-25）

- 录音中设备断开、采集流报错/中断，或连续 3 秒没有音频帧时，立即结束采集并提示“录音中断”。已完成的转写和未处理的有效分段仅留在内存，用户可选择“继续处理已录内容”；不自动写入可能不完整的句子。恢复沿用原输入框及十分钟过期规则。
- 音频帧持续到达但约 4 秒没有明显电平时，HUD 提示“没收到声音”，录音继续；电平恢复后清除提示。该判断用于排查设备，不是语音活动识别。
- 设置 → 语音提供麦克风选择和实时电平条。页面可见且没有正式语音任务时自动监听，不缓存音频、不提供试录或回放。离页、关窗、最小化或开始正式录音时停止监听；返回页面后恢复。未授权时提示开启麦克风权限。
- 引导试用中的采集异常只提示失败，不把试用音频转换成向外部应用输出的恢复任务。下次开始重新创建采集会话，不自动重启当前录音。

### 阿里云百炼语音识别（Issue #6）

独立后续变更：OpenAI 兼容语音识别已接入，并移除两个小米专用入口，不兼容或迁移旧配置。详见[实施方案](plans/openai-compatible-asr.md)；以下为 Issue #6 的历史范围记录。

- 增加“阿里云百炼”语音引擎，接入 DashScope 非实时 ASR HTTP 接口，首个验收模型为 `qwen-audio-3.1-asr-flash`。仅支持该接口的音频输入与 `output.text` 响应契约，不承诺所有百炼模型兼容。
- 现有入口保持“阿里云”名称，与“阿里云百炼”分别展示，原接口、凭据及配置键不变；其他引擎（包括两个小米入口）保持原行为。
- 设置与首次引导共用 Base URL、API Key、Model 三个输入项。Base URL 默认空，须含 `/api/v1`，也接受完整接口地址；Model 建议值为 `qwen-audio-3.1-asr-flash`，允许修改或清空。
