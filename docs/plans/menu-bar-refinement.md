# 菜单栏职责与展示优化方案

状态：代码已实现（2026-10-09），自动回归通过；菜单调整已打包试用，完整实机验收待完成。

日期：2026-10-09。

关联 Issue：[#13](https://github.com/isecret/MemoEcho/issues/13)。

## 1. 目标与边界

菜单栏提供稳定的全局入口和必要的任务操作；HUD 承担即时反馈；词典操作回到词典页。失败后仍能找回结果或继续处理，但首层菜单只显示一个恢复入口。

本轮沿用原生 `MenuBarExtra(.menu)`。保留当前运行期内、最长十分钟的单个恢复检查点，保持既有超时、手动重试和注入防重复规则。范围不包含历史记录页、音频落盘、新的任务中心或新的自动恢复机制。

本方案需要调整 PRD 中“菜单直接展示失败正文预览”“菜单撤销最近学习词条”等已有约定；用户已确认按本方案调整；已同步 PRD/TDD、任务拆分及协作约束。

## 2. 实施前的问题

依据 `MenuBarView.swift`、`SessionCoordinator.swift`、`PersonalDictionaryStore.swift` 和词典设置页核对：

- 错误全文、录音警告、结果正文预览、重试、检查输入框提醒、检查设置、丢弃、保留期限分别平铺；多个条件同时满足时，菜单高度和常用入口位置变化明显。
- 结果正文是按钮标题，实际动作是复制，操作意图不明确。
- 每个恢复检查点都显示“检查设置”，没有区分配置问题与临时调用失败。
- “撤销学习”及撤销失败信息放在菜单；最近学习标记在本次运行中没有计时失效，词典维护持续占据全局入口。
- `discardRecovery()` 与到期清理不清除对应的 `currentError`；任务回到 idle 也不清除它，因此恢复入口消失后旧错误仍可能留在顶部。
- 恢复状态与错误字段并非同一生命周期：新录音会清除 `currentError`。恢复说明不能只依赖“当前错误”，应绑定具体检查点，避免出现旧结果配新错误。

## 3. 推荐菜单结构

### 3.1 正常状态

```text
麦克风                  ›
────────────────────────
设置…                    ⌘,
关于 MemoEcho
────────────────────────
退出                     ⌘Q
```

保留麦克风选择的现有选项、勾选状态、设备刷新及忙时禁用规则。设置仍遵守首次引导完成后可见的约束；关于和退出行为保持现状。不增加常驻“空闲”标签、运行统计或新词提示。

### 3.2 有可恢复内容

```text
恢复上次输入            ›
────────────────────────
麦克风                  ›
设置…
关于 MemoEcho
退出
```

明确选用**子菜单**，名称为“恢复上次输入”，使用原生子菜单箭头；不加表示打开窗口的省略号。首层不显示失败正文、长错误或倒计时。进入子菜单不会开始重试、修改剪贴板或唤起另一个窗口。

### 3.3 当前任务可取消

顶部显示“取消当前任务”，由既有 `state.isCancellable` 决定。录音取消仍由 HUD/ESC 提供，注入阶段不新增取消操作。

活跃会话期间隐藏旧恢复入口，避免将旧结果操作和当前任务混在一起；隐藏不等于删除，原有期限继续计时。恢复处理中显示当前任务可用操作，不再允许从菜单重复发起恢复。

### 3.4 需要修复配置且没有可恢复内容

存在已确认、尚未修复的阻塞配置/权限问题时，顶部只显示“检查设置…”，打开对应设置页。不能仅凭残留的 `currentError` 判断应用是否仍不可用。

菜单展开仅读取已有状态，不主动请求权限、联网验证或切换应用。首次引导未完成时沿用现有自动引导与快捷键重开路径，不新增菜单“设置向导”。一次性的、没有可恢复内容的运行错误只走即时反馈，不长期占据菜单。

## 4. 恢复子菜单

以已生成文本、尚未发送写入事件为例：

```text
写入失败                     （不可点击的短说明）
────────────────────────
重试写入
复制结果
查看原因…
────────────────────────
丢弃本次结果
临时保留，退出后清除         （次要说明）
```

操作按检查点能力生成，不能把以上所有行无条件显示：

| 情况 | 可用操作与说明 |
| --- | --- |
| 识别失败且有可恢复音频 | 重试识别；查看原因；丢弃本次结果 |
| 整理/翻译失败且已有前置结果 | 重试整理/重试翻译；查看原因；丢弃本次结果 |
| 录音中断且有有效片段 | 继续处理已录内容；查看原因；丢弃本次结果 |
| 已有最终文本，尚未发送写入且原目标允许重试 | 重试写入；复制结果；查看原因；丢弃本次结果 |
| 已尝试写入但无法确认，或原目标已不可安全重试 | 复制结果；查看原因；丢弃本次结果；必要时显示“请先检查原输入框，避免重复粘贴” |
| 配置或权限需要修复 | 检查设置…作为主要动作；修复且满足既有重试条件后才开放阶段重试；可复制时仍保留复制结果 |

细则：

- “复制结果”只复制可供输出的最终文本，不把未润色转写当作完成结果；沿用既有输出质量边界。
- 复制必须由用户主动点击，成功显示已有“已复制”HUD；失败明确反馈并保留恢复数据，不能忽略剪贴板写入返回值。
- 复制成功不延长期限、不自动重试写入，也不立即删除恢复检查点。
- 重试继续调用现有恢复流程，原目标与会话身份仍需复核；打开菜单/详情不能导致把输出目标改为本应用。
- “查看原因…”使用轻量原生详情提示，仅展示这次失败的用户可读原因；关闭后仍可回到恢复入口。技术日志、原始响应和输入正文不进入菜单。
- “丢弃本次结果”沿用主动丢弃行为，清除对应数据与提示；不新增确认步骤。
- 保留期限继续以首次保留时刻计算，最长十分钟；打开菜单、复制、查看原因及失败重试不续期。子菜单用固定次要说明，避免原生菜单内不断刷新秒级倒计时。
- 入口判断以有效检查点及其真实可恢复数据为准；实现时审计旧的独立失败文本字段，确保不会出现仍有可复制结果但没有入口的情况。

## 5. 各界面的职责

| 信息/操作 | 展示位置 |
| --- | --- |
| 录音、Thinking、无声提醒 | HUD；菜单不重复展示完整警告 |
| 失败短分类及一个主要恢复动作 | HUD，沿用已确认的时长与交互 |
| HUD 消失后的找回与恢复 | “恢复上次输入”子菜单 |
| 失败原因详情 | 用户主动打开的详情提示 |
| 配置/权限修复 | 对应设置页 |
| 新学词条的即时提示 | 现有新词 HUD |
| 词条编辑/删除及其失败提示 | 设置 → 词典 |
| 麦克风切换、设置、关于、退出 | 菜单固定入口 |

词典统一复用“自动添加”筛选与已有编辑、删除操作。根据实机反馈，取消“最近添加”区域及独立撤销按钮，避免两个入口执行同一删除动作。新词即时提示继续由现有 HUD 承担。

删除只移除词条，不恢复输入框文本、不建立禁止学习名单；后续满足条件仍可再次学习。失败在词典页就地反馈。本次移除展示不调整词条排序或持久化格式。

## 6. 生命周期与一致性

- 菜单、HUD 及恢复动作基于同一份与 checkpoint ID 关联的展示状态，包含短分类、用户可读原因、是否需要设置和可用动作。
- 可用动作由业务层计算；菜单不得凭错误字符串自行猜测是否可重试。
- 活跃会话优先。新会话清空“当前错误”时，旧检查点如仍有效，其恢复说明不得丢失或绑定到新会话错误。
- 成功、主动丢弃、到期、检查点替换、退出分别执行既有数据清理规则，同时撤销对应菜单入口、HUD 旧按钮及过期回调。
- 仅清除与该检查点关联的旧错误展示；实际仍未修复的权限/配置阻塞应由就绪状态保留，不能为“菜单干净”直接宣称已恢复。
- 菜单已展开时发生到期或替换，点击动作仍须重新验证 checkpoint ID、有效期和允许状态；失效操作不执行，也不抢焦点。
- 不改动“已发出但不可验证”正常交付的既有处理：不因这轮菜单改造新增恢复入口或重复写入机会。

## 7. 实施拆分

1. **确认产品规则**：更新 PRD 的菜单预览、词典撤销、错误反馈及失败恢复描述，同步 TDD 和任务拆分。
2. **统一展示状态**：集中计算恢复动作和与检查点关联的原因；补齐成功/丢弃/到期后的界面清理，保持现有错误模型和恢复流程兼容。
3. **收敛菜单**：固定入口 + 至多一个上下文区域；恢复动作集中子菜单，复制使用明确文案，增加按需查看原因。
4. **迁移词典操作**：移除菜单撤销及其局部错误状态，词典复用已有删除操作、存储事务和失败提示，不另设最近添加区域。
5. **验证与验收**：先测状态与动作，再手工验证原生菜单、HUD、词典页和真实输入框；通过后再打包替换。

## 8. 验收标准

- [ ] 正常菜单只有麦克风、设置（可用时）、关于、退出；分隔线没有空白组。
- [ ] 一次失败至多增加一个首层恢复入口；首层无错误全文、正文预览、学习撤销或保留时限。
- [ ] 菜单关闭/重开以及 HUD 消失后，仍可在原有期限内找回可恢复内容。
- [ ] 八类失败、四个恢复阶段、部分录音、配置缺失、目标失效和已尝试写入分别展示正确动作。
- [ ] 无最终文本时无“复制结果”；配置正常的临时失败不机械显示“检查设置”。
- [ ] 复制成功有反馈，失败不误报成功、不丢失检查点；任何复制均来自用户动作。
- [ ] 旧失败到期/丢弃后不残留旧错误或 HUD 操作；真实未修复配置不被误清除。
- [ ] 活跃会话隐藏旧恢复菜单；结束后按原检查点生命周期决定是否恢复显示，不延长期限。
- [ ] 菜单已打开时到期/替换、快速连点、新会话到达等情况下，不调用旧动作、不重复写入。
- [ ] 打开菜单和详情不更改原注入目标；重试仍执行原有目标验证。
- [ ] 词典统一使用已有删除操作；保存失败能在词典页反馈，且词条数据回滚正确。
- [ ] 首次引导未完成、麦克风设备缺失、任务不可取消等现有边界不退化。
- [ ] 浅深色、长文案、VoiceOver、原生子菜单导航及设置页跳转通过实机验收。

## 9. 实施与验证记录

- 菜单根级移除错误、正文预览、录音警告和学习撤销；恢复统一子菜单，详情使用原生提示。
- 恢复原因绑定 checkpoint ID 与所属会话代次。动作重新核对 ID、期限、活跃状态；复制返回值决定反馈，失败保留结果。失效通知仅关闭匹配代次的旧失败 HUD。
- 恢复按原 ASR 平台读取配置；配置/权限修复后开放重试。菜单只读取缓存验证状态，完整但未验证的配置及瞬时请求失败不制造常驻菜单告警。运行前就绪检查仍保持严格。
- 已失效窗口的恢复不提供再次写入；菜单读取缓存的失效状态，不触发 AX 查询。真正重试仍由注入器检查原目标。
- 根据实机反馈移除词典“最近添加”区域与独立撤销；保留已有删除入口及事务回滚。
- 自动回归：175 项通过，覆盖恢复、HUD、词典存储与视图模型、就绪状态、云端/LLM 验证、实时链路及输出。最后针对已失效窗口、恢复及注入安全分支再跑 103 项，全部通过（与前轮部分重叠）。
- 上述验收清单保留为实机核对项；原生菜单导航、浅深色、VoiceOver、详情弹窗与真实输入框焦点尚未完成实机验收。菜单调整及移除词典“最近添加”区域已打包替换运行中的应用；后续 HUD 两字按钮调整尚未重新打包。

- 最终调整：移除最近添加区域后 33 项词典测试通过；HUD 两字按钮与恢复/布局专项 50 项通过。HTML 原型仅展示当前样式，JavaScript 语法、DOM 引用与历史对比清理检查通过。

数据仍仅保留在当前运行期内，原始十分钟期限不续期，不落盘。
