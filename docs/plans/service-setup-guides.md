# ASR 与 AI 服务开通指南方案

状态：待评审方案；本轮只设计文档，不编写未经核实的控制台操作教程。

## 目标

让首次接触云服务的用户完成：选择产品 → 注册与必要认证 → 开通服务 → 创建应用或凭据 → 复制参数 → 填入 MemoEcho → 验证 → 试说一句。

成功标准是用户能找到每个字段的来源并完成配置，不只是拿到一个 Key。明确区分“账号已有密钥”“对应产品已开通”“MemoEcho 验证成功”和“完整输入流程实测成功”。

## 文档组织

采用“一页入口 + 按厂商分篇”，避免把所有控制台操作堆进使用说明。

- `docs/guides/service-setup/README.md`：用户入口，说明 ASR 负责识别、AI 负责整理/翻译，二者都需就绪；按 MemoEcho 的服务名称提供直达链接。
- 同目录 `tencent.md`、`aliyun-nls.md`、`aliyun-bailian.md`、`volcengine.md`、`xunfei.md`、`mimo.md`：厂商教程，同厂商按产品设独立锚点。
- `openai-compatible-asr.md`：Audio Transcriptions 的地址、模型与凭据来源说明，区分本机服务与托管服务，不扩展为部署教程。
- `llm.md`：Chat Completions 通用配置说明和已核实的厂商示例。
- 截图放在 `docs/guides/service-setup/images/`，按厂商、步骤命名。

正式教程完成后，从 `docs/USAGE.md` 的首次准备、云端识别处链接入口，并更新 `docs/README.md`。本方案不修改根目录 `README.md`，不变更应用行为。

入口同时提供“使用本地 SenseVoice”和“已有云服务账号”两条路径。本地无需 ASR Key，但后续 AI 整理仍需独立配置，不能写成全流程离线。

## 每篇教程的统一模板

1. **选对产品**：对应 MemoEcho 哪个选项；最终需要拿到哪些字段；是否有多个容易混淆的产品。
2. **开始前准备**：账号、认证、地域、开通与计费条件。是否需要充值以官方当前要求为准，不承诺永久免费。
3. **进入控制台**：提供官方控制台直达链接，同时给出从首页进入的菜单路径，避免深链失效后无路可走。
4. **开通目标服务**：一步一个操作，写出按钮名称与完成后的页面标志；明确哪一步可能涉及付费确认。
5. **创建应用和凭据**：按实际产品要求创建；需要权限时写清对应授权，优先使用官方支持的最小必要权限，不为方便直接授予管理员权限。
6. **复制并填写**：逐字段表格，包含“MemoEcho 字段 / 控制台字段 / 获取位置 / 填写示例”。密钥只用 `<你的 API Key>` 等占位符；URL 和模型 ID 单独提供可复制代码块。
7. **验证与试用**：等待应用状态就绪；再在测试框完成一次录音、AI 整理和写入。ASR、AI 分别验证，不能用模型列表加载成功代替完整验证。
8. **常见卡点**：按现象给出下一步检查位置，如认证失败、产品未开通、模型无权限、地域不一致、额度不足、地址或协议不匹配。
9. **官方依据与核验日期**：链接到具体产品、密钥、接口文档，标注适用版本、核验日期与验证程度。

每篇开头增加“已有账号，直接找参数”的快捷索引，允许用户跳过注册和开通步骤。

## 实施顺序

1. **建立清单**：逐项对照设置页、配置模型和产品文档，确定所有入口、字段与共享关系。
2. **完成两个样篇**：先写火山 ASR（产品与凭据分支多）及百炼 AI（覆盖 Base URL / API Key / Model），验证模板能解决实际卡点。
3. **补齐全部 ASR**：覆盖表中所有现有入口，共用步骤复用，产品开通和验证步骤分开。
4. **补齐 AI 示例**：逐家核实 Chat Completions 支持情况，写出明确的地址、模型 ID 来源和权限要求。
5. **走读与实测**：让没有对应平台经验的读者按教程操作；分别记录公开文档核实、登录控制台核实、MemoEcho 真实调用和完整输入实测，未做的项目标为未验证。
6. **发布导航**：接入使用说明与文档导航；应用内“如何获取参数”链接作为后续可选工作，不包含在本轮文档任务中。

## 验收与维护

- 用户从入口能直接找到当前选择的服务，不必猜厂商产品名称。
- 每个必填字段都有明确来源、填写位置与示例，不使用“自行获取 Key”等跳步表述。
- 每条路径覆盖从开通到验证；同厂商不同凭据、地域和协议的分界有明确说明。
- 官方链接可打开；截图与文字一致；示例不含真实凭据。
- 已确认的事实与待验证步骤分开，未真实联调不标记“验收通过”。
- 每篇记录最近核验日期与适用应用版本；厂商改版、用户反馈找不到入口或应用新增配置字段时定向复核。发布新版本时检查字段是否变化，无需重复改写全部教程。

本轮交付仅为方案。正式教程阶段仍需核实厂商当前页面，部分登录后操作与真实调用可能需要可用账号及已开通的服务，不能用公开文档推断为已实测。
