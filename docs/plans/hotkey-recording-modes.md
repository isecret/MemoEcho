# 录音快捷键的三种方式（Issue #8）

设置页与首次引导共用「录音方式」：

| 选项 | 提示 |
| --- | --- |
| 单按 | 按一下开始，再按一下结束。 |
| 双按 | 连按两下开始，再连按两下结束。 |
| 按住 | 按住说话，松开提交。 |

## 行为

- 默认右 Command + 单按。普通组合键单按在按下时切换；纯修饰键单按保留候选 HUD，干净释放后切换，参与其他组合键时取消候选。
- 双按要求两个完整按下／释放周期，两次按下间隔不超过 400ms，每次按住也不超过 400ms。普通组合键可保持修饰键，只释放主键；纯修饰键须释放目标组合。首按无 HUD、音效或录音。超时后下一次有效按键作为新的首按；连续三按只触发一次。
- 按住立即请求录音，无长按门槛。普通组合键在主键释放或必需修饰键提前释放时结束；纯修饰键在目标修饰键全部释放时结束。松开只处理该手势启动的 session，短于 500ms 仍静默取消。
- 重复 keyDown 不算新按键。无关普通键、系统功能键、额外修饰键会打断双按；纯修饰键按住录音参与其他快捷键时取消录音，不提交。录音中的 Shift+Tab 翻译切换保留；Shift 按下暂作为该组合的候选，其他普通键仍取消。
- 识别、润色、注入和恢复处理期间忽略录音手势，不缓存下一次触发。录音及处理时禁止修改录音方式和快捷键。
- 录制快捷键只采集一次组合并保留所选方式；录制期间暂停全局手势。睡眠、监听暂停、重新注册清除手势并取消未结束的按住录音，不因失去释放事件而提交。
- 请求录音与实际设备启动之间松开或取消，不得留下迟到启动的录音。设备中断沿用现有错误及恢复流程。

## 实现

`general.hotkey.triggerMode` 为 `singlePress` / `doublePress` / `hold`。缺失字段读为单按，编码单按时省略字段，保持既有快捷键确认指纹。方式修改使用现有注册、保存、确认事务，失败回滚原监听及配置。

`HotkeyGestureRecognizer` 只处理有效按下、释放、打断与时间戳，不依赖 AppKit、计时器或录音器。`HotkeyManager` 将 Carbon、物理组合键、纯修饰键三条输入路径归一化；按住事件同步送达主线程，携带手势编号。`AppCoordinator` 将编号与 session ID 绑定，只有匹配的释放／取消才可结束录音。

### 快捷键设置交互补充

- 保留「单按 / 双按 / 按住」选择器；引导页位于“设置快捷键”标题下方，设置页分别展示“录音快捷键”和“按键方式”两行：前者为键帽与“更改…”按钮及录制提示，后者为左对齐的三段选择器与随选项变化的使用说明。直接修改即时校验、注册并保存，失败保留旧配置；仅录制键位时暂停全局快捷键，不使用编辑浮层或二次确认。引导页继续使用三段选择器。
- 录制只采集键位，不按点击次数或持续时间猜测方式；切换方式保留键位，录制期间禁用方式切换。
- 三种方式共用新快捷键校验：允许非空纯修饰键组合；普通键必须搭配 Command、Option、Control 或 Fn，单独普通键及仅 Shift 的组合不允许；Esc 保留为取消。
- 录制提交与应用保存使用统一校验，不合法时显示原因并保留原配置与监听。历史配置加载不自动重置；用户重新设置时遵循新规则。
