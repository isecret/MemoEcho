# 浏览器富文本输入框写入确认修复方案

状态：下述第一阶段方案已被 2026-10-10 用户确认的简化粘贴策略取代；现行约束以 PRD 8.7/8.8 与 TDD 11 为准。本文保留第一阶段诊断与历史决策。

日期：2026-10-10。

## 1. 目标与依据

修复 ChatGPT 可编辑 DIV 中“文字已写入，HUD 仍提示写入失败”的问题。采用按能力处理的通用路径，不增加网站或浏览器名单。

事实依据为 PRD 8.7 / 8.8、TDD 11、当前实现以及本次复现。用户已确认按本方案实施；第 3 节行为调整已同步 PRD/TDD，真实验收仍待完成。

### 1.1 本次观察

- Chrome 将现场编辑器暴露为 `AXTextArea`，AX DOM class 包含 `ProseMirror`；不能根据外观单行或 AX role 判断它是原生 `input`。
- 用户清空测试输入框后，AXValue 仍返回长度为 11 个 UTF-16 码元的内容，末尾包含换行，选区为 `(0, 0)`。
- 下一次写入后，读回长度为 6，采样中的 AX 元素身份保持一致。11:28:26 的应用日志记录注入耗时 1229ms 后失败。
- `TextInjector` 根据“写入前全文按选区替换”为预期值。将空框的 11 个码元当作原文时，预期会保留它们；写入后的实际值没有这些内容，因此无法匹配。
- 本次没有记录正文，也没有取得 DOM 对照证明那 11 个码元具体来自哪一段占位文字或辅助内容。它们不能被当成可通用硬编码删除的占位符。
- 现有失败日志只记录 `text_injection_failure`；外部采样未与应用内每次读取逐条关联。后续实机验收需补充应用内的脱敏确认原因，排除同时发生的读取异常。

### 1.2 设计参考边界

参考异步粘贴实现中“投递与正文确认分离”的处理方式：系统接受发送事件，不等于目标已收到文字。

MemoEcho 保留自己的定向发送、会话互斥、剪贴板所有权检查和约 1 秒保护窗口，不照搬固定恢复延时，也不引入文本历史保存。

## 2. 推荐方案

**发送前严格保护目标；发送后把正文验证作为独立确认结果，不再把无法验证等同于写入失败。**

第一阶段不尝试猜测或清除 AXValue 中的占位内容。修复不依赖识别 ChatGPT，也不依赖 DOM 注入、浏览器插件或页面脚本。

### 2.1 发送前

保留现有检查：权限、会话有效性、原目标身份、字段/窗口边界、组字状态、正文与选区是否变化，以及剪贴板所有权。

- 未找到目标、目标已经切换、权限缺失等：阻止输出，沿用相应错误。
- 原本可读的目标在发送前失去快照：继续阻止输出，不降级为窗口投递。
- 剪贴板备份失败、写入失败或明确没有发送粘贴事件时：沿用现有受保护的 AX 回退。
- 一旦已经发送粘贴事件，不允许再发送、改走 AX 补写或自动重试。

### 2.2 投递与确认

内部结果区分两个维度，不增加配置键，也不要求新增全局 SessionState：

```swift
enum OutputDelivery { case pastePosted, axAccepted }
enum OutputVerification {
    case verified
    case unconfirmed(VerificationReason)
}
```

建议原因为有限枚举：`valueMismatch`、`snapshotUnavailable`、`targetChanged`、`composing`、`unchangedValue`。它们仅解释确认结果，不携带正文或 URL。取消仍按现有取消路径处理。

- `pastePosted`：定向粘贴的按下/抬起事件均已发出，不等于浏览器消费完毕。
- `axAccepted`：AX 写入返回成功，不等于正文已验证。AX 回退只有在事件未发送时才可能执行。
- 任一投递路径接受操作后，立即发出一次 `outputDispatched`，HUD 开始收起。
- 在现有约 1 秒保护窗口内继续确认，沿用可靠的全文精确匹配作为 `verified` 条件。保留“不变正文不能作为成功证明”等保护。
- 正文不匹配、快照不可读或发送后的目标变化只返回 `unconfirmed`；不再抛出通用注入失败，也不让 HUD 收起后再次弹出失败。
- 发送后发现明确目标变化，继续使本次确认永久失效；不尝试重新找框、重新激活或补写。变化发生前后到底在哪个位置消费事件，不能靠校验推断。
- AX 写入返回失败仍按执行失败处理，并保留 `outputAttempted = true`，防止可能存在的副作用被重复执行。

### 2.3 用户可见行为

| 情况 | HUD | 菜单与恢复 | 词典学习 |
| --- | --- | --- | --- |
| 发送前阻止输出，或执行接口明确失败 | 沿用权限/写入失败提示 | 按既有规则复制；仅无写入尝试时可重试 | 不启动 |
| 已投递且正文验证通过 | 投递时收起，不重复通知 | 清除本次恢复内容 | 仅符合原有 polish 条件时启动 |
| 已投递但不能验证，包括不可读目标 | 投递时收起，不提示成功或失败 | 保留“恢复上次输入”中的主动复制与丢弃 | 不启动 |
| 发送后取消或会话已被替代 | 按现有取消/代际规则收起 | 不由旧任务重新发布恢复项；已有内容按原期限清理 | 不启动 |

未确认结果的恢复说明为“未确认写入”；详情为“已尝试写入，请先检查原输入框，避免重复粘贴。”只提供主动复制、查看说明和丢弃，不提供自动重试或正文预览。

恢复结果只保存最终文本和必要状态，释放原始音频、转写中间值、上下文和不再使用的目标引用。复用单个内存恢复槽，最长十分钟；已有检查点的期限不因重试或查看菜单延长。退出清除，下一条结果替换，不落盘、不自动复制。

HUD 收起不代表注入互斥已经结束。继续保持一个 active session，直到确认/剪贴板清理完成，之后回到可开始下一次录音的状态；本轮不引入跨会话剪贴板任务。

### 2.4 剪贴板与取消

- 验证通过可以提前恢复；未确认则在保护窗口结束时恢复。
- 只恢复自己仍拥有的临时内容，期间用户新复制的内容优先。
- 发送后取消仍完成必要的保护窗口与清理，但不发出晚到的成功、失败、学习或菜单更新。
- 所有返回、异常和取消路径只释放一次 lease，清理后解除互斥。

## 3. 已确认的产品变化

用户在评审方案后明确要求开始修复、打包并重启验证，确认实施以下两项：

1. **可读输入框已投递但校验失败时，改为中性未确认结果。** 原 PRD 8.7 明确要求这类情况提示写入失败；新方案改为不打断 HUD，菜单保留主动复制。
2. **不可读目标正常投递但未验证时，也保留单个临时结果。** 原 PRD 8.8 要求清除这类结果。新方案统一未确认结果的恢复体验，仍限定内存、十分钟、无历史页。这是保留条件变化，不能在实施时静默调整。

确认记录：2026-10-10，用户要求“开始修复，修复完成后打包然后重启应用我验证”。实现使用既有 `InjectionPath` 表示投递方式，`Confirmation.verified / unconfirmed(reason)` 表示确认结果，不新增重复的投递状态类型。

## 4. 代码职责与伪代码

| 文件/模块 | 变更职责 |
| --- | --- |
| `Platform/TextInjector.swift` | 分离投递与确认；统一投递通知；返回有限确认原因；保留发送前保护与 lease 生命周期 |
| `Platform/FocusedElementTextSnapshotReader.swift` | 只在必要时补充脱敏读取失败原因；本阶段不加清空占位文字或模糊匹配逻辑 |
| `Domain/Coordinators/SessionCoordinator.swift` | 正确处理 verified/unconfirmed；仅 verified 开启学习；未确认结果保留；代际隔离 |
| `Domain/Services/SessionRecoveryCheckpoint.swift` | 增加非错误的未确认输出状态；剥离不需要的中间数据；禁止重试 |
| `Domain/Coordinators/AppCoordinator.swift` 与菜单视图 | 让无 failure 的未确认结果也能生成恢复入口，绑定正确检查点 ID |
| `Domain/Coordinators/HUDFeedbackController.swift` | 复用 `outputDispatched`；确保一次通知且无校验超时后的失败闪现 |
| `Domain/Services/DiagnosticsLogger.swift` | 在成功与未确认路径都输出投递路径、确认结果、有限原因和耗时 |

```text
检查原目标、会话、权限、选区
备份剪贴板并再次核对目标及所有权
尝试一次定向粘贴；明确未发送时才允许受保护的 AX 回退
若执行失败：保留现有失败处理和防重复标记
否则：标记 outputAttempted，通知 outputDispatched

在约 1 秒保护窗口内验证：
    可靠全文匹配且未失效 → verified
    其他情况 → 收集有限原因，不重新写入
按所有权恢复剪贴板并解除互斥

如果取消或代际已变化：不发布旧结果
否则如果 verified：清除恢复项，按原规则启动词典学习
否则：保存 finalText-only 的 unconfirmed 恢复项，不发 processingFailed
```

诊断日志只输出枚举、布尔值和耗时，不输出正文、占位文字、选区文本、URL、页面标题、DOM 或用户内容 hash。保留系统日志现有位置和保留策略，不新增文件日志。

## 5. 测试与验收

### 5.1 自动回归

1. 使用合成空框辅助内容构造现场形状：before 长度 11、选区 `(0, 0)`；粘贴后原辅助内容消失。修复前抛错，修复后返回 unconfirmed；粘贴一次、AX 写入零次、剪贴板正确恢复。
2. 原有普通文本精确替换继续返回 verified；中文、emoji 的 UTF-16 选区、选中替换、多行与中间插入均覆盖。
3. 值始终不变、值不相关、只改变选区、快照中途不可读：不误标 verified，不启动学习，不重复写入，保留手动复制。
4. 发送前目标切换、组字、选区变化、权限缺失：输出被阻止；保持原有安全断言。
5. 发送后焦点短暂丢失又恢复：仍不能 verified；保留未确认结果，不补写，不弹明确失败 HUD。
6. 不可读字段与窗口目标：投递即收起 HUD，保护窗口与窗口连续性检查继续，完成后提供未确认结果恢复。
7. AX 回退成功且验证通过、成功但未确认、返回失败三条路径分别验证；失败可能有副作用时禁止重试。
8. 新复制优先、备份超时、恢复只执行一次、互斥、发送后取消和旧会话晚到的回归全部保留。
9. `SessionCoordinator` 验证 unconfirmed 不进入错误路径，结果只保留内存十分钟、过期清理、退出清理、被新结果替换；不延长旧期限。
10. HUD 验证一次 outputDispatched 后不会因确认超时重现失败，旧会话结果不影响新一代 HUD。菜单验证无 failure 时仍有复制入口、无自动重试、无正文预览。

重点运行 `TextInjectorTests`、`SessionRecoveryTests`、`SessionTextOutputTests`、`HUDFeedbackControllerTests` 及协调器相关测试，再运行项目完整测试与构建。只使用合成内容、可注入 driver 和命名剪贴板。

### 5.2 真实验收

| 场景 | 验收要求 |
| --- | --- |
| 当前 Chrome / ChatGPT 空可编辑 DIV | 连续 10 次合成短句：每次实际写入一次；零次“已写入却报失败”；未确认时菜单能复制 |
| ChatGPT 已有正文，中间插入、末尾追加、选中替换、多行 | 原有正文不丢失、不重复，确认结果与实际读取证据一致 |
| 普通 HTML input / textarea、原生文本编辑器 | 实际写入正常，可靠场景继续 verified |
| 不可读目标，如终端 | 正常投递不报失败，未确认结果可主动恢复 |
| 注入前切换应用/输入框 | 不向错误目标写入 |
| 投递后切换焦点、浏览器更新辅助功能树 | 无补写，不伪称 verified，结果可找回 |
| 期间主动复制新内容 | 新剪贴板不被恢复覆盖 |
| 投递 API 成功但目标未消费 | 不误标 verified；用户能从未确认结果复制，确认方案的体验取舍 |

实机使用合成测试文字，不提交网页消息。记录版本、场景、投递结果、确认原因、是否重复和剪贴板恢复结果，不记录原文或截图中的真实用户内容。完成前只可宣称自动回归通过，不能宣称 ChatGPT 兼容性修复已验收。

## 6. 实施顺序与风险

1. 确认第 3 节两项产品决策，同步 PRD 8.7/8.8、TDD 11、E7/E8 的任务与验收说明，以及相关菜单方案。
2. 先加能复现现场误报的合成回归，再实现投递/确认拆分和最小诊断字段。
3. 接通协调器、HUD 与临时恢复项；确认整个链路不会丢失未确认结果或重复注入。
4. 完成自动检查后打包试用，按 5.2 实测；用户未要求部署时不替换当前安装版本。

主要取舍：事件发出但目标未消费时，不会立刻弹红色失败提示。通过不宣称 verified、保留复制入口与精确诊断来处理；不使用超时后补写来掩盖问题。

第一阶段修复投递结果与提示的语义，并阻止 AX 表示差异造成误报；不承诺已经正确解析所有富文本编辑器的正文。后续只有取得稳定、可测试的语义证据，才改进空编辑器快照提取，从而提高 verified 比例和词典学习覆盖率。

## 8. 用户确认的简化策略

用户明确要求直接采用备份剪贴板、模拟粘贴、延迟恢复的策略，取消过度严格的输入确认。

- 仅剪贴板粘贴，移除 AX 回退、注入后全文校验与未确认恢复状态。
- 正文或选区变化、快照不可读不再阻止正常粘贴；保留目标身份、权限、组字和剪贴板归属的基础保护。
- 发出事件立即收起 HUD，固定等待约 500ms 后恢复剪贴板；期间用户新复制优先，取消仍完成清理。
- 投递完成清除恢复记录；学习使用可选快照自行验证，不阻塞输入。
- 未取得目标消费回执，不承诺目标一定接受；不以自动重发补救。

验证记录：简化后全量测试 775 项、0 失败、1 项外部服务按条件跳过；最后补充投递后失效窗口监控后，注入与恢复回归 97 项全部通过。真实网页验收待用户完成。
