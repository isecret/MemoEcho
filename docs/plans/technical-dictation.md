# 口述技术文本还原（Issue #33）

跟踪：[Issue #33](https://github.com/isecret/MemoEcho/issues/33)。用户于 2026-11-07 确认开始实施。产品边界见 PRD §8.5，技术入口为 `LLMProvider` 固定润色 Prompt。

## 问题与首轮范围

语音已识别出字母和符号读法时，润色仍可能保留中文“点”、引入空格、句末标点或错误大小写。目标是让显式口述的技术片段可直接输入，不依赖具体 ASR 厂商。

| 类型 | 合成口述 | 目标技术字串 |
| --- | --- | --- |
| 隐藏文件 | 点 ENV、点 gitignore | `.env`、`.gitignore` |
| 文件扩展名 | package 点 json | `package.json` |
| 多级域名 | p 点 example 点 com | `p.example.com` |
| 邮箱 | dev 艾特 example 点 com | `dev@example.com` |
| 路径 | 斜杠 usr 斜杠 local | `/usr/local` |
| 端口 | localhost 冒号三千 | `localhost:3000` |
| 明确 IP | IP 地址是一九二点一六八点零点一 | `192.168.0.1` |
| 明确版本 | 版本号是 v 一点二点三 | `v1.2.3` |
| 显式分隔符 | user 下划线 name、两个短横线 version | `user_name`、`--version` |

技术字串嵌在句子中时保留整个句意；仅输入技术字串时不额外加标点、Markdown 或解释。

## 歧义与保护

- “我晚点到，还有一点事情”中的“点”属于普通中文，不转换。
- “ENV 环境变量需要检查”不把 ENV 变成 `.env`。
- “user name”不能推断为 `userName` 或 `user_name`。
- 用户明确要求字面保留时遵从；普通数字、时间不套用 IP／版本规则。
- 已正确的 URL 查询参数／片段、路径大小写与内部空格保留；不擅自补协议、www、后缀、路径或命令参数，不根据品牌猜域名。
- 常见 `.env`、`.gitignore` 可按惯用写法恢复；明确的大小写要求优先。
- 素材仍不可信，不执行命令或修改角色／JSON 协议。符号还原不把 `correction_applied` 设为 true；同时存在明确改口时继续遵循原改口规则。

## 实现

流程保持：完整 ASR → 固定 Prompt 润色 → 既有 JSON parser / renderer / normalizer → 可选翻译 → 注入。只增加 Prompt 规则，不增加本地正则替换、配置项、请求或协议。翻译保持现有流程，本次不增加独立翻译保真规则。

## 验证

- 合成场景位于 `scripts/fixtures/technical-dictation.json`；纯技术文本精确比较，句内片段按保留符号的字面断言。普通中文、字面保留、大小写、空格、提示注入分别验证。
- `scripts/tests/test_evaluate_polish_prompts.py` 使用错误变体确认评测器能检出漏点号、错误大小写、多余标点、补协议和误改命名。
- `LLMProviderTests` 验证模型已返回的技术字串经过真实 Provider 解析、渲染和会话处理后逐字符保留，不以 mock 证明模型质量。
- 新旧 Prompt 使用当前配置服务做合成对照，分别有无合成词典／窗口上下文；不读取个人词典、窗口正文或历史录音。模型请求可能产生服务费用。

```sh
python3 scripts/evaluate-polish-prompts.py --run --suite technical --baseline-ref 9f29577 --output /tmp/technical-eval.json
python3 scripts/evaluate-polish-prompts.py --run --suite standard --baseline-ref 9f29577 --output /tmp/standard-eval.json
python3 -m unittest discover -s scripts/tests -p test_evaluate_polish_prompts.py
```

基线必须指向变更前的提交；提交后不能继续用更新后的 HEAD 充当旧 Prompt。评测脚本只发送合成文本和参考信息，输出不包含服务地址、模型标识或凭据。结果仅代表当前模型的小样本，不替代真实语音、不同模型与目标编辑器的手工验收。

技术枚举场景允许 `plain_text` 或 `list`，因为现有产品契约是保守地“可整理”为列表；两种形式都必须保留 `.env` 和 `package.json` 的技术字串。输入采用“第一是点 env”，避免把“第一点”同时用作枚举措辞和文件名前导点，导致测试意图不唯一。标准列表回归继续使用原断言。

`--versions candidate` 可只评测当前 Prompt，`--case technical_dot_env` 与 `--profile bare` 可定向复测；请求记录包含合成输入和 Prompt 的 SHA-256 以区分迭代。网络错误仅记录类型和数值错误码，不记录原始错误正文。

## 验证记录（2026-11-07）

Debug 构建和 49 项定向 XCTest 通过；评测器错误变体回归 5 项通过，`git diff --check` 通过。

最初 26 个技术场景的新旧 Prompt 对照使用同一组输入，每条分别测试基础 Prompt 和合成参考信息，共各 52 次请求。旧 Prompt 为提交 `9f29577`。初版规则发现 `../` 丢点、`user-name` 丢字母、大小写／空格误改等问题后继续迭代，以下“当前”数字来自最终源码的整轮验证，而非从多个版本挑选成功响应拼接。

| 样本 | 请求数 | 样例断言通过 | 返回文本但断言失败 | 连接失败 |
| --- | --- | --- | --- | --- |
| 旧 Prompt，最初 26 个技术场景 | 52 | 26 | 20 | 6 |
| 当前 Prompt，同样 26 个技术场景 | 52 | 43 | 0 | 9 |
| 当前 Prompt，完整 30 个技术场景 | 60 | 51 | 0 | 9 |
| 当前 Prompt，19 个标准回归场景（含短回应重复抽样） | 44 | 39 | 0 | 5 |

“同样 26 个技术场景”是完整 30 个场景的子集，不能与下一行相加。最终整轮共 104 次请求：90 条响应通过断言，14 次连接失败。14 次均为 `SSLEOFError`，脚本因此返回非零状态，不将其计为语义成功。普通句内断言检查关键片段、禁用片段和改口标记，不等价于全部句意／表达质量的自动评估。

陌生域名场景两个 profile 在整轮中均未取得响应，随后仅为该场景补测 2 次，均返回 `p.zenvora.com` 并通过断言。这样 30 个技术场景每个至少取得一条通过响应，但部分场景的某个参考 profile 仍因连接失败缺失，不能宣称完整矩阵全部通过。首次失败记录保留，不用补测覆盖。完整标准回归 19 个场景均至少有一条通过响应。

最终整轮及陌生域名补测的 92 条模型响应，使用项目真实 Swift `StructuredPolishParser`、`StructuredPolishRenderer` 和 `PolishTextNormalizer` 回放，均通过解析、产生非空正文；plain_text 的字符在渲染和规范化后保持一致。回放跳过 14 次未取得响应的连接失败，不把回放当作新的模型质量评测。

验证仅使用合成输入、合成词典和合成窗口参考；没有发送真实录音、个人词典或窗口正文。不同批次的连接失败数不同，不能直接按总请求成功率推导模型质量或端到端速度。Prompt 还原依赖 ASR 的字母／拼写证据，不能恢复完全缺失或含混的陌生域名字符。当前样本不保证模型在所有输入中稳定保真，也不替代真实语音到编辑器的手工验收。

### 测试版试用反馈：句首“嗯”（2026-11-07）

用户反馈句首“嗯”出现频繁，并确认关注“嗯，后接完整句子”的场景。日志不含正文，无法追溯该次 ASR 与润色的具体输入输出。冻结调整前本地 Prompt 的初次 8 次合成请求仅返回 3 条，均正确删除停顿词，其余 5 次连接失败；尚不能据此证明此前技术文本规则引起了回归。

按用户确认的偏好细化编辑边界：无明确回应含义、位于完整陈述／提问／想法／操作描述之前的“嗯”视为起头停顿；标点本身不使其成为独立回应。独立“嗯”、明确回应“嗯，可以”“嗯，我知道了”、疑问与引用仍保留，也不得添加原文没有的“嗯”。继续仅由模型按语义编辑，没有新增客户端正则删除。

评测脚本新增 `--suite filler`，覆盖 14 个场景：句首动作、想法、提问、技术文本、推测、重复停顿、无原始停顿词、明确回应、引用、独立短回应、疑问与顺序表达。调整后分别带／不带合成参考共 34 次请求，34 次通过样例断言、0 连接失败；34 条模型响应通过项目真实 Swift parser／renderer／normalizer 回放。49 项定向 XCTest、5 项评测器测试通过。该记录仍不替代用户实际语音复测。

可用 `--baseline-source /path/to/frozen/LLMProvider.swift` 对比未提交的本地 Prompt，避免将更早 HEAD 误当作正在试用的版本。此次调整已构建、校验签名并重启 `MemoEcho Dev`，未替换 `/Applications/MemoEcho.app`。

### 测试版试用反馈：普通回应重复（2026-11-07）

用户明确期望“好的好的”合并为“好的”。冻结调整前本地 Prompt，针对“好的好的”“好的，好的”“收到收到”“可以可以”分别有／无合成参考共 8 次真实模型请求，8 次均保留重复，部分只添加标点。原始模型 JSON 已含重复，证明此样例的保留发生在模型阶段，客户端正常渲染也不会去重。

规则细化为：普通回应连续重复默认合并一次，保留一次回应即可；不能只插标点，保留后文。按词／短语判断，允许处理明确的起头卡顿重启；正常叠词、情绪表达、明确强调、引用／逐字保留要求、不同说话人或事件中的重复，以及技术文本的重复字符仍保留。普通去重不标记明确改口。没有新增本地逐字压缩或正则处理。

`--suite repetition` 覆盖 16 场景、32 请求：28 条模型响应通过断言，4 次连接失败。句首清理及独立回应回归另有 4 场景、12 请求：10 条通过、2 次连接失败。仅为上述两组中完全未取得响应的“重复回应后接句子”和“句首起头停顿”补测各 2 次，共 4 条全部通过；失败记录不覆盖，部分 profile 仍缺失。合计 42 条取得的响应通过断言和项目真实 Swift parser／renderer／normalizer 回放，6 次连接失败不计成功。

定向 XCTest 49 项、评测器测试 7 项与 `git diff --check` 通过，构建校验签名后已重启 MemoEcho Dev。此次具有调整前保留重复的合成复现，但仍需用户真实语音复测，不宣称所有口头重复和强调语境都能稳定区分。


### 发布前补充：网址协议小写（2026-11-07）

用户要求显式口述的网址协议名保持小写，例如 HTTPS://www.example.com → https://www.example.com。这条局部规则优先于技术字母大小写保留，只修改协议名；路径、查询参数、片段及文件名 HTTPS.txt 保留原有大小写，不补未口述的协议。新增 5 个合成场景验证直接网址、口述分隔符、HTTP、大小写尾部和普通文件名。
