# HUD 展示优化方案

状态：已确认实施（2026-10-09）；客户端代码已调整，待完整实机验收。

日期：2026-10-09。

关联 Issue：[#12](https://github.com/isecret/MemoEcho/issues/12)。

预览：[`../hud-prototype.html`](../hud-prototype.html)；历史探索保留在 [`../hud-failure-prototype.html`](../hud-failure-prototype.html)。

## 1. 目标与范围

让用户读清新学词条、失败原因和下一步动作，避免短文案被挤压、长内容被固定窗口裁切。保留现有黑色胶囊、七条声波、Thinking 动效及低干扰反馈方式。

本次覆盖 SessionCoordinator / AppCoordinator 到 HUDFeedbackController、HUDState、HUDContentView、HUDLayout、HUDWindow 的展示链路，以及引导页复用的录音/Thinking 组件。不是对项目全部模块的代码审计。

不改变识别、润色、翻译、文本注入或恢复检查点的业务逻辑；不增加自动重试、自动复制、处理阶段拆分或输出正文预览。权限拖拽浮窗为独立界面，本次不改。

## 2. 当前问题与证据

| 位置 | 当前行为 | 影响 |
| --- | --- | --- |
| HUDFeedbackController.learnedTermNoticeText | trim 后按 Swift Character 取前 4 个，超出加省略号 | 中文、英文术语都过早截断；后续布局无法补回原文 |
| HUDLayout.windowSize / HUDWindow | 固定 240 × 52.8pt 面板 | 内容宽度变化后，缺少统一的面板尺寸约束；长词/多行不能只改 SwiftUI |

| HUDContentView.resultPayload | 原因与动作拼为“写入失败 · 重试写入” | 状态与点击目标不易区分，整条胶囊可触发动作 |
| HUDLayout.resultWidth | 无动作失败固定为 86.4pt | 未按图标、内边距、字距和正文完整测量 |
| HUDFeedbackController | 新词 1.8s，无动作失败 1.2s | 长内容和失败原因阅读时间偏短 |
| PRD 与实现 | PRD 写“新词：{term}”，实际只显示词条 | 需要统一事实依据与最终产品文案 |

“固定面板裁切”等属于代码识别出的布局风险，需原生实机验收；HTML 为近似绘制，不能作为 SwiftUI 像素级证据。

## 3. 状态清单

HTML 当前收录 26 个代表性展示组合，覆盖以下状态及全部现有恢复动作；动作与错误由会话检查点匹配，不枚举所有笛卡尔积。

| 类别 | 内容 | 行为 |
| --- | --- | --- |
| 快捷键候选 | 低亮静态声波 | 未采集音频；确认后转录音，取消后隐藏 |
| 录音 | 取消 + 七条声波 + 完成 | 保留 ESC 取消与现有音效时序 |
| 信号缺失 | 取消 + 没收到声音 + 完成 | 录音继续，信号恢复后回到波形 |
| 模式提示 | DICTATE / TRANSLATE | 替换录音内容约 650ms，之后恢复 |
| 处理 / 恢复处理中 | THINKING | 不拆分底层阶段；恢复处理不播放开始录音音效 |
| 词典提示 | 词典图标 + 新学词条 | 不展示“新词：”前缀，保证词条可读面积 |
| 复制确认 | 勾选 + 已复制 | 仅用户主动复制结果后出现 |
| 无动作失败 | 录音中断、缺少权限、资源缺失、没听清、识别失败、润色失败、翻译失败、写入失败 | 短分类提示，详情仍在现有入口 |
| 带动作失败 | 对应短分类 + 恢复按钮 | 检查设置、重试识别、重试整理、重试翻译、重试写入、复制结果、继续处理已录内容 |
| 隐藏 | 空闲、成功、取消、短录音 | 无单独的成功/取消胶囊 |
| 已投递但不可验证 | 隐藏 | 延续现有行为：HUD 淡出，后台继续剪贴板保护；不宣称正文已确认 |

## 4. 拟议展示规则

以下为本次已确认方案，PRD/TDD 随实施同步更新。

### 4.1 新词：先测量，再决定换行

- Controller 保留 trim 后的完整词条，不再在数据层统一截取 4 个 Character；空字符串不显示新词 HUD。
- 沿用词典图标与 12pt semibold 字体。保持词条原始大小写，不强制 uppercase。
- 短词胶囊自然宽度，最小 86.4pt；最大宽度 `min(320pt, 当前屏幕可见宽度 - 32pt)`。
- 使用真实字体、字距和内边距测量；完整词条单行能放下时不省略。到上限后最多两行，行高目标 18pt，垂直内边距 6pt，两行胶囊高度约 50pt，圆角约 17pt。
- 两行仍无法放下时，仅末行尾部省略；不滚动、不跑马灯、不继续缩小字体。拉丁长串允许按 grapheme 边界换行，不拆开 emoji 或组合字符。
- 完整词条仍保留在词典页，VoiceOver 使用完整内容；HUD 不新增全文工具提示或自动打开词典。
- 展示时间按最终布局确定：单行 2.4 秒，多行 4 秒。时间从内容可见后计起，不能被旧状态的隐藏任务提前结束。

### 4.2 失败：状态与动作分区

- 无动作失败按正文、图标、字距和内边距测量自然宽度，最小 86.4pt，不再强制固定宽度。停留 2.4 秒。
- 有动作时左侧是警示图标和短分类，右侧是独立按钮，中间细分隔线；只有按钮触发恢复，不再给整个胶囊附加点击恢复行为。
- 保留已有动作文案，不把“重试整理”静默改名为其他阶段。最长动作“继续处理已录内容”必须完整展示。
- 总宽度受同一 320pt/屏幕安全宽度上限约束；正常桌面按单行显示，空间不足时允许动作区两行、面板增加高度，不能省略动作名称或挤没状态。
- 胶囊最小高度 34pt，动作点击区域至少 28pt 高；提供 hover、pressed 和 VoiceOver 状态，不把整条样式变成大卡片。
- 默认 5 秒；鼠标停留于胶囊或辅助功能聚焦动作时暂停剩余倒计时，离开后继续剩余时间，不重新计满 5 秒。
- 操作执行期间防重复触发，旧动作在会话/检查点变化后失效。动作一旦触发按业务反馈进入 Thinking、设置页或复制确认；HTML 仅模拟这些结果。
- 保持非激活面板，不抢键盘焦点；不为普通 Tab 导航把 HUD 变为 key window。辅助功能焦点支持需单独实测，不假定浏览器焦点行为等同 NSPanel。

### 4.3 录音与处理

- 候选、正常录音、Thinking 保持 105.6 × 31.2pt 基准及现有颜色、七条波形。
- 无声提示按整段“没收到声音”测量空间，使用 12pt 字号；同时保留取消/完成按钮。宽度自然扩展，参考原型约 138pt，最终值由原生字体测量确定。
- 无声恢复和模式切换时平滑回到对应宽度，不残留文案或波形，不重启录音或播放多余音效。
- Thinking 保持单一处理状态；备份超时/业务错误仍通过既有失败映射展示，不加底层错误说明。
- 已复制仍停留 1.2 秒；成功/取消/短录音继续直接隐藏。

### 4.4 面板尺寸、定位和动画

- 增加统一展示测量结果，至少包含胶囊宽高、面板宽高、行数与停留时长。View 与 Window 使用同一结果，禁止两边分别维护固定尺寸。
- 面板四周保留透明余量（初始建议水平 10pt、垂直 6pt，最终以描边/缩放动画不被裁切为准）。面板最大宽度也必须落在屏幕可见范围内。
- 保持可见屏幕水平居中和既有底部/Dock 避让；高度增加时向上生长，底部锚点不跳动。
- 会话首次显示时按当前鼠标所在屏幕选屏，后续内容变宽/变高沿用该屏幕，不因鼠标移动突然跳屏；显示器移除时回退当前可用屏幕并重新钳制。
- 保留 `.nonactivatingPanel`、Spaces/全屏辅助行为；只有录音控制和失败动作需要响应鼠标，普通新词/Thinking 继续穿透。
- 大尺寸切换先确保容器能容纳内容再转场，缩小时先完成内容切换再收缩；避免文字、图标在过渡中被旧边界截去。
- 动画与隐藏任务使用代次或可取消任务隔离。新会话优先，旧提示不得覆盖录音、让 HUD 半透明停住或提前关闭新状态。
- 连续学习事件避免叠层；沿用最新提示策略，同一会话的新词提示可替换前一提示，重新按布局计时。不要新增无限提示队列；录音/处理中的晚到提示不得抢占当前状态。
- 减少动态效果开启时，停止 shimmer/波形装饰动画和弹跳尺寸变化，保留静态状态辨认和必要淡入淡出；不改变业务时序。

## 5. 实施拆分

1. **统一产品规则**：评审本方案；PRD 更新词条前缀、截断、停留时长、动作点击范围；TDD 更新测量、面板尺寸与生命周期。同步任务拆分文档，不将预览视为已落地。
2. **布局模型**：在 HUDLayout 中抽出可测试的测量与屏幕钳制方法；完整原文与展示测量分离。语义状态保持现有业务边界，不做配置/错误模型的破坏性迁移。
3. **原生布局**：HUDContentView 新词两行、失败动作分区、无声提示扩宽；HUDWindow 动态面板尺寸；消除 controller 的旧 hosting 固定 frame 与窗口尺寸不一致。
4. **生命周期**：HUDFeedbackController 删除 4 字截断，按测量选择时长；补充暂停倒计时、操作防重复、新会话抢占与过期回调保护。
5. **同步复用和预览**：引导页复用的录音/Thinking 外观保持一致；HTML 随最终尺寸和文案更新，历史失败态原型继续标注历史用途。
6. **测试与实机验收**：回归通过后打包，在真实屏幕、Dock、输入框及 VoiceOver 下检查。未完成前不关闭 Issue。

## 6. 验收标准

### 布局与文案

- [ ] 2 字、4 字、5 字、12 字中文以及英文术语不再固定只显示 4 个字符。
- [ ] 测试中英混排、连续英文长串、emoji、组合字符、空白词条；没有断裂字符、字形压缩或多余空提示。
- [ ] 单行能容纳时完整展示；必要时两行；极长词只在第二行末尾省略，词典页仍为完整数据。
- [ ] 八类失败与七种动作均可读，最长恢复按钮完整展示，状态和动作不重叠。
- [ ] “没收到声音”完整显示，取消/结束按钮可用，恢复波形后尺寸正常。
- [ ] HUD 四周描边、图标和动画不被面板裁切；无透明遮挡区域拦截正常输入。

### 交互与状态

- [ ] 单行新词 2.4s、多行 4s、无动作失败 2.4s、带动作失败 5s、已复制 1.2s、模式提示 650ms。
- [ ] 带动作 HUD 悬停/辅助功能聚焦暂停倒计时，离开后按剩余时长继续；只点状态不会触发恢复。
- [ ] 连点动作最多发起一次业务操作；会话变化后旧回调无效。
- [ ] 快速录音→Thinking→失败→重试、新词→新录音、连续新词等切换不残留、不闪烁、不被旧任务隐藏。
- [ ] 不抢原输入框焦点；复制仍由用户主动触发；已发送粘贴不因 HUD 改动产生重复写入。
- [ ] 成功、取消、短录音和不可读目标已投递保持原有消失行为。

### 平台与回归

- [ ] 浅深背景、Retina/缩放屏、底部与侧边 Dock、Dock 自动隐藏、多屏不同坐标/缩放和全屏应用验收。
- [ ] 屏幕可见宽度约束下始终位于安全区域；变高向上展开、底部位置稳定；断开显示器后正常回退。
- [ ] VoiceOver 读出完整词条、失败原因与独立动作；减少动态效果时仍能辨别状态。
- [ ] HUDLayoutTests 覆盖真实测量、单/双行、上限、屏幕边缘与定位；不以复制实现常量作为唯一断言。
- [ ] HUDFeedbackControllerTests 覆盖时长、暂停/恢复、旧任务失效、动作防重复与状态优先级；引导预览和注入恢复链路回归。

## 7. 当前交付与限制

已完成：

- SwiftUI/NSPanel 已按本方案调整，完整词条分行、失败按钮分区、无声提示扩宽、动态面板与底部定位均已实现。
- 提示倒计时在窗口显示完成后开始；悬停与辅助功能焦点分别控制暂停，退出后续计剩余时间。旧代次动作、重复点击、过期隐藏任务与晚到新词受到保护。
- 面板在透明边缘/圆角外穿透鼠标；仅在交互态监听鼠标移动以更新命中区域，不监听或转发键盘事件。首次录音重新选屏，同一会话的状态变化沿用该屏幕。
- AppCoordinator 不再在旁路事件到达前无条件清理恢复按钮。词条内容不再插值写入 HUD 日志；词条恰好为“已复制”时也不误认成复制确认。
- PRD、TDD、任务拆分和 HTML 原型已同步。HTML 保留改动前/优化后对比，浏览器绘制仍是近似预览。

验证记录（2026-10-09）：Debug 构建通过；HUD 专项 53 项（Controller 38、Layout 15），失败恢复 25 项、文本输出 3 项、引导协调器 14 项，共 95 项相关测试通过。测试覆盖多语言/emoji 分行、极长词末行截断、最长动作、动态原生面板尺寸、底部锚点、屏幕安全区、透明边缘命中、倒计时暂停/续计、重复操作和过期回调。合成数据的真实 NSPanel 缓存渲染已检查：两行词条、末行截断、最长恢复按钮、无声提示均可读。测试产物包含 PNG 附件；`ImageRenderer` 无法正确导出带辅助功能焦点的恢复按钮，按钮视觉检查以真实 NSPanel 缓存渲染为准。

复测修正（2026-10-09）：根据用户观察增加全部 8 类失败 × 7 种恢复动作的单行断言，复现了“写入失败”等四字分类被挤成 3+1 两行。原因是文字区域被对半分配，但状态与动作字距不同，状态所需宽度略大；之前只检查最长按钮并校验拼接后的完整文字，未约束常见组合的行数。现改为总宽度未触及上限时分别保留两侧实测宽度，只有到屏幕宽度上限才压缩换行。同时增加短词/组合字符的宽度边界测试，以及常规“写入失败 / 重试写入”的真实 NSPanel 渲染与 PNG 附件。修复后本轮 94 项测试全部通过，常规恢复 HUD 与最长恢复 HUD 均为单行；长词的两行展示仍按已确认方案保留。

边框复测修正（2026-10-09）：用户观察测试 HUD 的边缘比旧版更模糊、有锯齿。原生 NSPanel 像素检查稳定复现圆角轮廓外的描边残片（2× 渲染下 32 个像素，排除轮廓外 1pt 范围内的正常抗锯齿）。本次将 Capsule 改为可支持多行的 RoundedRectangle 时遗漏了原有外层裁切；仅恢复与背景相同的圆角裁切后，异常像素降为 0，原生渲染中两侧的多余短边线消失。新增 `testNativeHUDBorderStaysInsideRoundedOutline` 先失败后通过；最终相关回归 95 项通过。测试窗口使用同一套生产 HUD 组件，此问题属于这次绘制改动的回归，不能归因于测试环境降低画质。跨屏缩放清晰度仍需实机验收。

尚未完成：安装包替换及真实输入框主链路验收、VoiceOver 实际焦点切换、多屏拔插/不同缩放/Dock/全屏矩阵、透明边缘的真实跨应用点击。自动化测试与原生合成渲染不代替这些验收，Issue 保持打开。
